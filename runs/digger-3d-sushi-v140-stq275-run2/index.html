The game plays, but the board is nearly invisible: the terrain renders almost black and only the lit digger, emeralds, bags, enemies and spawn portal show; the board is readable only with the debug overlay. The session was stopped at a 92,152-token prompt by Sushi's GPU-memory admission check (maximum context at KV8 with this pack: 87,684 tokens) and resumed with Pi's window lowered to 80,000.

What was checked

  • Sushi refused the 92,152-token request: about 3,568 MB needed against 3,329 MB available, reporting a maximum context of 87,684 tokens at KV8 and prefill chunk 512. Free GPU memory at the first admission check was 5,366 MB. Pi had not compacted because its window was 131,072.
  • Resumed in the same Pi session with "continúa" and contextWindow 80,000; Pi compacted four times and the largest later prompt was 63,468 tokens.
  • tsc --noEmit passed, npm test reported 28/28 PASS and npm run build (tsc + Vite) produced the 581 kB bundle when rerun after the session.
  • Browser check with scripted input: title screen with attract mode; the digger moves and digs (debug view player (7,3), digging=1), enemies spawn and chase, lives go from 3 to 0 while idle and the game-over overlay appears.
  • Visual defect: src/three/terrain.ts colours the terrain 0x24170e and 0x1c130c under dim lighting, so the dirt, tunnels and board render almost black in the normal view.
  • Console: two 404 errors on page load, not identified at check time; the two published builds of the same day show the same pair, which is Chrome's automatic /favicon.ico request. This build was not re-served to confirm.
  • The model's final report lists bugs its tests found and fixed: bag self-collision, double crush score and a test-harness arity bug. It reports that level 2 loads after the emeralds are cleared; that was not checked.
  • No build of this attempt is published.

Limits of this evidence

Sushi 1.4.0 (MLX 0.32.3), banner at line 3 of the process log, was started through the workstation's log launcher with the same arguments as its production Sushi service except port 12346: 131,072 context, KV8, MTP with MTP-head KV quant, prefill chunk 512, one prefix-cache entry, 20 GB SSD prefix cache, 16,384 output tokens, temperature 0, memory preflight skipped and /metrics on. The engine was loaded before the session; model load time is excluded. Sushi does not report TTFT in this log, and peak memory was not sampled. The Pi provider entry (sushi-275: maxTokens 16,384, contextWindow 131,072, lowered to 80,000 for the resume) was removed after the runs; those values come from the operator's notes. Wall time is the sum of the two segments (30.6 and 33.4 min) and excludes the pause between them and the compaction that opened the resume.
