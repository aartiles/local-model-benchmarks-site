28 October 2026 · Agentic game · isometric 3D

Digger 3D · Sushi 1.4.0 · 2.6bpw pack

Session completed Local run

Built a complete, playable Digger 3D with the production 2.6bpw pack on Sushi 1.4.0: TypeScript check, 28/28 self-tests and the production build pass, and the browser shows a title screen, a readable isometric board with emeralds, gold bags and the spawn gate, digging, and the game-over overlay. The level starts mostly excavated, which the operator judged less faithful to the original Digger than STQ run 3's board full of dirt.

What was checked

  • tsc --noEmit passed and 28/28 self-tests passed when rerun after the session the way the model ran them (esbuild bundle of scripts/run-tests.ts, then node; plain node --experimental-transform-types fails on extensionless imports); npm run build produced the bundle. There is no npm test script.
  • Browser check with scripted input: title screen with a HIGH/LOW quality toggle over the live board; an isometric diorama with an undiggable outer dirt ring, raised dirt blocks, glowing emeralds, gold bags, a red spawn gate and a LEVEL 1 FIRST SHIFT banner. Movement and digging worked (+1 popups, gems 6 to 5, score 25); lives went from 2 to 0 within about 20 s idle and the game-over overlay appeared.
  • Console: two 404 errors, both Chrome's automatic /favicon.ico request at the server root; the page references no favicon. The published Sushi 1.2.4 build shows the same two requests when served the same way. No page errors.
  • The model's final report lists fixes it made: an undiggable outer ring, the UI built before the canvas (a constructor innerHTML had destroyed it) and the camera fit.
  • No response reached the 16,384-token output limit; the largest was 9,708 tokens. Free GPU memory at the first admission check was 7,771 MB, against 5,557 MB for STQ run 3.
  • A full level, a level transition and game over by play were not checked beyond the above.

Limits of this evidence

Sushi 1.4.0 (MLX 0.32.3), banner at line 3 of the process log, was started through the workstation's log launcher with the same arguments as its production Sushi service except port 12346: 131,072 context, KV8, MTP with MTP-head KV quant, prefill chunk 512, one prefix-cache entry, 20 GB SSD prefix cache, 16,384 output tokens, temperature 0, memory preflight skipped and /metrics on. The engine was loaded before the session; model load time is excluded. Sushi does not report TTFT in this log, and peak memory was not sampled. The Pi provider entry used for this run (sushi-26test: maxTokens 16,384, contextWindow 80,000) was removed after the runs; those values come from the operator's notes. Requests whose output budget Pi clamped below 16,384 put prompt plus budget at about 76K tokens, consistent with that window. The generated project and check captures stay on the workstation.
