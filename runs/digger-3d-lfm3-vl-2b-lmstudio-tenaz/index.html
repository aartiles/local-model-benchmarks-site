28 October 2026 · Agentic game · isometric 3D

Digger 3D · LFM3-VL 2B · LM Studio 0.4.26 · Tenaz

Session failed Local run

Blocked at the first bootstrap step after 3 sessions and 3 min 24 s: no spec was accepted and no task card or code was written. LFM3-VL 2B never opened the project's CHALLENGE.md; in every session it searched the disk by absolute paths and wrote spec.md and map.md outside the project, twice at the benchmark repository's root and once in the home folder, so Tenaz found neither file in the project.

Compare attempts →Task prompt →Measurements ↓

What was checked

  • Preflight: tools, reasoning and vision worked (the model named both colours of the test image). Tenaz 0.2.0 reported the prefix cache as not reported and continued without --allow-weak-engine.
  • 65 of 68 tool calls (28 ls, 19 find, 8 read, 6 write, 4 bash) named paths outside the project; the other 3 were find calls without a path. The model read the benchmark repository's AGENTS.md and design.md and tried a brief in the home folder that does not exist. It never read CHALLENGE.md or the project's brief.
  • When session 001 listed the repository root, a .tenaz folder with spec.md and map.md was already there, left by the LFM3 1.7B run 40 minutes earlier; this run overwrote both files in sessions 001 and 003, and wrote a second pair in the home folder in session 002. The operator moved both pairs out of those places after the run.
  • Tenaz's sandbox was off (sandbox false). With --set sandbox=true, Tenaz confines the agent's writes to the project and the package caches, so these writes should have failed in front of the model instead of landing elsewhere.
  • No project code exists, so nothing was built, run or played.

Limits of this evidence

Three sessions are a small sample: this records a failure to find and use the project, not the model's coding ability. The project lives in a folder inside the benchmark repository, so a model that searches upwards finds the repository and the previous run's stray files; a project outside the repository and Tenaz's sandbox would both have limited that. LM Studio does not report cached tokens or TTFT to the client, so cache figures and rates come from llama.cpp's own timing lines and no TTFT is recorded. Tenaz's memory samples followed the LM Studio app process, not the llama-server process that held the model, so no model memory figure is recorded. No build of this attempt exists.
