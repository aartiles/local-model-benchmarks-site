First of three attempts under the 2026-10-02 Sushi run's settings (16,384-token output limit). The model wrote a 3,244-line project whose TypeScript check and 28 self-tests pass, but the page never loads the game: index.html has no script tag, so the production build contains no JavaScript. The session ended on a reasoning-only response with no final report.

Compare attempts →Measurements ↓

What was checked

  • tsc --noEmit passed and npm run selftest reported 28/28 PASS when rerun after the session.
  • Browser check: the built page shows a static title screen; Enter does nothing because no script is loaded.
  • Diagnosis on a separate copy, not counted for the run: with the script tag added the simulation starts but the canvas stays black, because the custom vignette and CRT ShaderPass shaders read a uniform named tex while ShaderPass fills tDiffuse. With the composer bypassed the board renders, but the digger moves without input, walks off the board and lost all three lives in about 15 s without input.
  • No build of this attempt is published.

Limits of this evidence

Splash 1.4.0 (Homebrew) served the model with --max-context=131072 under the name Qwen3.8-Flash-Next-Splash-Q2_0. The startup log reports 128K context, routed experts resident in memory (32,402 MiB) and the per-layer n-gram table streamed from its file (27,465 MiB on the SSD), and warns that with --verify-rows auto greedy and seeded outputs can differ from run to run for this MoE target. Splash had released its weights after 600 s idle before runs 2, 3 and the 64K-output variant and restored them in about 8.4 s before the first request, which is inside the first request's TTFT. Splash reports TTFT and decode rate, not a standalone prefill rate, draft acceptance or peak memory.
