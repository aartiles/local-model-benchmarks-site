What was checked

  • Runner final state COMPLETE on 19 November 14:52:43.291 UTC: 13 tasks done, none pending. Bootstrap passed its three steps on the first attempt (13 tasks, 22 requirements). Final review cycle 1 returned ACCEPT with verify passing and 22 requirements covered, three (R20-R22) by hand. `verify --all` passed 45 of 45 model-written checks again after the run; not a hidden acceptance suite.
  • Configuration: the same as run 1 (same brief, checkpoint, engine scripts, Pi 1.4.0, thinking off, temperature 0.8, vision, generic engine, Tenaz defaults, sandbox off) except the runner: Tenaz main 2f1b04c, built from the repository, which writes each harness's own files again before every session and names a session that removes .tenaz/private. Launched with --allow-weak-engine because the preflight still asks for reasoning when thinking is off; that preflight passed cache, tools and vision.
  • Runner events: no session stopped or failed. T006's first review returned CHANGES and attempt 2 passed; every other task review returned ACCEPT. Two replans added no tasks. One response stopped at the output limit. Watchdog steers only (context and turn pacing).
  • Played on 19 November by Claude with Playwright in headless Chromium against the production build, with real keyboard and mouse input and pointer lock reported as granted (headless Chromium grants none). This build has no debug hook, so results come from screenshots and the source.
  • Must have results: walking stops at the closed door; strafing and walking back move the view; mouse turning through movementX; straight walls; brick, stone and wood textures plus a panelled door; textured floor and ceiling; side and distance shading visible, not measured; the barrel cut off by a wall edge in the spawn view; Space opens the door onto a corridor where two enemies walk toward the player; left click fires with a muzzle flash and lowers the ammo bar, a hit enemy flashes, and after six shots both enemies were gone from view (the code kills at the third hit and has a lying-down sprite, which was not caught on a frame).
  • Faults found in play: the on-screen controls hint is four colour bars (green WASD, cyan mouse, orange Space, red click) with no text; health and ammo are bars without numbers; enemies walk to the player and never attack (no damage code); no win or end screen.
  • Vision: no image refusals. The model read eight different images in 20 read calls, including its spawn, turned and door captures, a contact sheet and the floor and ceiling textures.
  • Engine metrics: a fresh Splash process serving only this run. Its 445 summaries are 6 preflight requests and 439 run requests. All 439 proxy records match a Splash summary one-to-one and in order by (prompt, output, cached); per session, the totals equal the Pi usage Tenaz journaled.
  • Memory: Tenaz's 310 host samples run from start to end. Wired memory went from 27.6 GiB at the start to about 47 GiB after 35 minutes and stayed there (median 47.0, maximum 48.9). Memory pressure stayed normal in every sample and 0.02 GiB was swapped in, with Chrome and Claude in use on the same machine. Tenaz sampled Splash's Python parent, not its engine process, so no engine footprint is recorded.
  • Public artifact: the reviewed static build (vite build --base ./ from the final project commit 3d54c0e, unchanged source) and its spawn view at 1280x720. The prompt is the author's and is not republished; the project, raw logs, journal and sessions stay in the ignored local archive.
