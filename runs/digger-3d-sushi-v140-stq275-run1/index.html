Session failed Local run

The model never opened prompt.md. After listing the folder it invented a different task, a Next.js and Flask pixel-art canvas game titled Sushi Quest, and finished in under 8 minutes with a report claiming a complete implementation. Nothing in the project relates to Digger 3D.

Compare attempts →Task prompt →Measurements ↓

What was checked

  • Pi session: 22 tool calls, none of which reads prompt.md; the first are a directory listing and a tool-version check, then package.json, Next.js configuration, a Python sprite generator, React page code and a Flask launcher.
  • The model also ran pip3 install --break-system-packages flask pillow on the host, outside the project folder.
  • The project folder also held a stray .started file when the session began.
  • Per the operator's notes, four first-turn probes in clean folders with the same pack all read the prompt, so the behaviour was not reproduced; the 2.6bpw pack did not show it.
  • No build of this attempt is published.

Limits of this evidence

Sushi 1.4.0 (MLX 0.32.3), banner at line 3 of the process log, was started through the workstation's log launcher with the same arguments as its production Sushi service except port 12346: 131,072 context, KV8, MTP with MTP-head KV quant, prefill chunk 512, one prefix-cache entry, 20 GB SSD prefix cache, 16,384 output tokens, temperature 0, memory preflight skipped and /metrics on. The engine was loaded before the session; model load time is excluded. Sushi does not report TTFT in this log, and peak memory was not sampled. The Pi provider entry (sushi-275: maxTokens 16,384, contextWindow 131,072) was removed after the runs; those values come from the operator's notes. This process also served run 2.
