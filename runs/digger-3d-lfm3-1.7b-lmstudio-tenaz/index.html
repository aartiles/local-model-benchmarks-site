Session failed Local run

Blocked in Tenaz's bootstrap after 10 sessions and 30 minutes: no task card was accepted, no task started and no game code was written. LFM3 1.7B wrote a 26-requirement spec and a verify script that checks only that node and npm are installed, then failed the task-card step six times, across one operator resume. Its first two sessions wrote the spec outside the project.

Compare attempts →Task prompt →Measurements ↓

What was checked

  • The first launch stopped at Tenaz's preflight: LM Studio reports no cached prompt tokens, so Tenaz saw no prefix reuse. LM Studio's log shows the second preflight turn reusing the slot (661 of 2,713 prompt tokens evaluated). The run was relaunched with --allow-weak-engine.
  • Spec and map: sessions 001 and 002 wrote spec.md and map.md into a .tenaz folder at the root of the benchmark repository that holds the run folder, so Tenaz found neither in the project; session 003 wrote them in the project: 26 requirements.
  • Verify: accepted on the first session. The script prints a passing check whenever node and npm are installed and checks nothing in the project.
  • Task cards: session 005 listed task IDs instead of requirements under each card, leaving all 26 requirements without a task; 006 and 007 wrote cards without frontmatter. Tenaz blocked at 13:40 UTC; the operator resumed once for three more attempts. Session 008 also wrote into .tenaz/checks, which Tenaz reverted; 010 was stopped after 20 turns without reading or changing anything new. Blocked again at 13:55 UTC with 26 cards, 18 of them without frontmatter, and one card depending on a missing task.
  • Many tool calls used absolute paths outside the project: the run folder above it (mostly the project's own files with project/ missing from the path) and the benchmark repository's root, where the model read README.md and AGENTS.md. Tenaz's sandbox was off.
  • No project code exists, so nothing was built, run or played.

Limits of this evidence

LM Studio does not report cached tokens or TTFT to the client, so the cache figures and rates here come from llama.cpp's own timing lines, not from Tenaz. No TTFT is recorded. Tenaz's memory samples followed the LM Studio app process (about 0.3 GiB), not the llama-server process that held the model, so no model memory figure is recorded. The project lives in a folder inside the benchmark repository, which the model found when it searched upwards; the stray spec.md and map.md it wrote at the repository's root were later overwritten by the LFM3-VL 2B run. No build of this attempt exists.
