Session failed Local run

BLOCKED in Tenaz's bootstrap after 32 min and 5 sessions: no task card was written, no task started and no game code exists. The spec (31 requirements) and verify were accepted on their first attempts; the task-card step failed three times. Each of its three sessions ended on one reply that used up the 16,384-token output limit on reasoning alone (16,384 reasoning tokens each, at medium, low and low effort), with no file written.

What was checked

  • Runner final state BLOCKED at 9 November 23:33:23.053 UTC: bootstrap failed 3 times at step 3 of 3 (task cards), with no task cards in .tenaz/tasks/ and requirements R1 to R31 without a task. Steps 1 (spec and map, session 001) and 2 (verify, session 002) were accepted on the first attempt.
  • Task-card sessions: 003 (medium effort, 5 requests), 004 and 005 (low effort, after Tenaz saw the previous reply stop at the output limit; 4 requests each). Each made a few short tool-calling requests and then one reply that stopped at 16,384 output tokens, all of them reasoning, with no tool call. 0 writes in each. Tenaz logged a context-pace steer early in each session (turn 4, 3 and 3), before the cut reply.
  • Runner: Tenaz 0.6.0 (36f2131), the merge of Tenaz PR #48 into main, not tagged or released, unmodified (binary sha256 4111c04d...fbbf8). All Tenaz parameters at their defaults; no --engine flag, so Tenaz used its generic engine; vision and medium thinking set at init. No pauses, no edits to run.json and no edits to model-written files.
  • Engine: the TensorFold native 1.2.5 process started for the run before this one (same pid in all 74 of Tenaz's memory samples and in the operator's notes). Its arguments come from that run's start script and agree with the server log: one startup banner with greedy sampling, the DFlash2 drafter snapshot and a 131,072-token context; a 6,144 MiB prompt cache in the cache lines; the three cut replies stop at exactly 16,384 tokens. The version comes from tensorfold --version written by the same script.
  • Engine metrics: all 41 proxy records match TensorFold 'done' summaries one-to-one by (prompt, cached, output) tokens; forward-earliest and backward-latest matches agree. They are the 41 consecutive summaries after this run's 6 preflight summaries and the last before the server was stopped. tenaz status reports the same figures: 41 requests with engine timings, prompt cache 86.5%, TTFT median 3.84 s, decode 48.18 tok/s output-weighted.
  • Memory: Tenaz's 30-second samples show pressure normal throughout, the TensorFold process at 47 to 49 GiB and 3.9 MiB swapped in.
  • No project code exists, so nothing was built, run or played. The brief is the author's and is not republished; the project, raw logs, journal and sessions stay in the ignored local archive.

Limits of this evidence

The run used the same Tenaz build, brief, model, drafter and engine arguments as an earlier 36f2131 run with a 2 GiB prompt cache, changing only the cache to 6 GiB; that run passed the task-card step on its second attempt. With the 6 GiB cache the prompt cache share rose, but the task-card step failed all three attempts the same way: the model reasoned until the 16,384-token output limit before writing any card, at medium and at low effort. One execution; the step's outcome may depend on small differences in the earlier steps' files. Raising the output limit is the obvious next variable; it was not tried in this run.
