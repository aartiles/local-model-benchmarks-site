Build and task checks

The session notes record a successful TypeScript check and Vite production build, plus 28/28 simulation self-tests. The interaction smoke check covered game start, movement, collecting a gem, and firing with cooldown.

Manual acceptance did not include completing a level or checking bags and the bonus mechanic. The session notes also list bloom/post-processing, hit-stop, and danger-reactive music as unfinished polish.

Metric interpretation

Input and output counts are cumulative across model calls. Repeated conversation context can be counted again; cached input is already included in the input total, and reasoning output is already included in output. The 20.32 tokens/s figure divides total output by end-to-end wall time. It is not a model decoding benchmark.

Limits

No token-by-token emission timestamps or reliable time-to-first-token measurement were retained. The run is one task attempt, not a repeated score. Compare the reported game checks on the challenge page; do not compare its aggregate token rate with local Sushi decode or prefill rates.

An early self-test left a browser-local high score of 20,005. The test was fixed so later runs would not change that value, but the existing value was not cleared. It is browser storage, not data embedded in the published game build.

The public record omits the original prompt, Codex transcript, session log path and session identifier. The gameplay image is a user-provided capture optimized for the site; it documents one visible state and does not verify completion of the full challenge.
