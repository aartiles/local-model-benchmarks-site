Task requirements & full brief

The post shows a 10-second video of its own result, made with DeepSeek v4.1, Blender MCP and DeepSeek Harness; its settings are not recorded, so runs here are not compared with it. Runs are scored with hidden acceptance cases read from final.blend in Blender as it renders (the pagoda's tiers, its geometry and that of its surroundings, materials, and what changes over the frame range) and from the video (format, frame count, motion). The detail thresholds are floors set before any run, so a blockout fails them; passing them says nothing about how the scene looks, which is judged by eye. Each run also counts how many of the builders' calls went through the MCP server. The language model, the MCP Blender and the renders share the Mac's 64 GB. No transcripts are published.

  • The post's prompt, word for word: an ultra-detailed pagoda in Blender, built through its MCP server, animated, in an immensely complex scenario.
  • Every other choice is left to the model: the pagoda's style, the scene around it and how it moves.
  • Build in a running Blender 5.2.1 through Blender Lab's MCP server, one call at a time within 300&nbsp;s, and save final.blend from it.
  • Keep the pagoda's objects in a collection named Pagoda, and render the whole animation to an H.264 MP4 of at least 1280&times;720.
  • Offline: check and render with a separate headless Blender, and look at your own stills.

How to read this comparison

Compare the generated builds and the checks recorded for each attempt. There is no normalised quality score, and the cloud task’s cumulative token totals and end-to-end rate include repeated context, reasoning, tool calls and waiting — they are not comparable with local per-request decode or prefill rates. The method page sets out which figures can and cannot be set against each other.

Attempts run with Tenaz used the open-source runner at github.com/aartiles/tenaz. It plans the brief into tasks, builds each in a fresh agent session and accepts it only when its checks pass and a reviewer agrees. The method page describes it and the runners before it.
