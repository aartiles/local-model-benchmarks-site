Task requirements & full brief

The attempts had different briefs and execution scopes. Astra used one Codex task and generated assets during that task. Tenaz received those exact assets and a revised brief, then planned, implemented and reviewed the game across separate fx sessions. Mistral Large 4 received the same assets and revised brief as Tenaz, in one Mistral Vibe session. Qwen 3.8 27B pi-adapted received them too, under Tenaz with Pi. The run sheets define each measurement. Physical iPad use remains unverified.

  • Build a static 3D time trial through an alpine pass, with obstacles, split steering and pedal controls, and checkpoint timing.
  • Calibrate a stationary toy car to a point on the tablet screen, or drive the textured digital coupe in chase view.
  • Provide collision penalties, sound, pause, replay and persistent calibration. Check the game in a browser and report the devices tested.

How to read this comparison

Compare the generated builds and the checks recorded for each attempt. There is no normalised quality score, and the cloud task’s cumulative token totals and end-to-end rate include repeated context, reasoning, tool calls and waiting — they are not comparable with local per-request decode or prefill rates. The method page sets out which figures can and cannot be set against each other.

Attempts run with Tenaz used the open-source runner at github.com/aartiles/tenaz. It plans the brief into tasks, builds each in a fresh agent session and accepts it only when its checks pass and a reviewer agrees. The method page describes it and the runners before it.
