Voxel Pagoda Garden

One prompt to a coding agent: a creative, detailed voxel scene of a pagoda in a garden with cherry blossoms, in a single HTML file that opens in Chrome. One Pi session, no runner. Qwen 3.8 Flash Next set the first result; Hy4-Flash repeated the same prompt, once with Qwen's settings where Hy4 allows and once with Hy4's defaults; Ternary Bonsai 2.5 27B on Splash repeated it at temperature 0 and 0.9.

Task requirements & full brief

The same prompt, byte for byte, in each run; it is not published. The Hy4-Flash runs differ from the Qwen run in engine version (Sushi 1.8.0 against 1.0.5), Pi version, drafter (DFly2 against MTP), thinking level (Hy4 has no medium, so it ran at high with a 16,384-token budget) and working folder (empty against one with unrelated files). The Bonsai runs use Splash 1.7.3, a DFlash2 draft made for Qwen 3.8 27B and Pi's medium thinking as medium, with no thinking budget. Throughput is compared in the temperature 0 reports rather than in charts, because the Qwen record states its decode figure as a weighted mean of request rates. Each build is a single run.

  • Design an elaborate, colourful voxel scene of a pagoda in a garden with trees, including cherry blossoms.
  • Use any libraries, but deliver one HTML file that can be pasted and opened in Chrome.

How to read this comparison

Compare the generated builds and the checks recorded for each attempt. There is no normalised quality score, and the cloud task’s cumulative token totals and end-to-end rate include repeated context, reasoning, tool calls and waiting — they are not comparable with local per-request decode or prefill rates. The method page sets out which figures can and cannot be set against each other.
